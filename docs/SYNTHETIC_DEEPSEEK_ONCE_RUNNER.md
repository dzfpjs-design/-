# 独立合成业务建议单次调用实验

该工具只针对原有隔离测试流程生成的合成审批检查点，在新建本机 PostgreSQL、独立临时资料区和加密响应暂存中运行。它不是正式工作区或 8766 的发送入口。默认 `fake` 模式使用本机 TLS 假服务，返回模拟失败响应；`live` 模式必须显式提供已经打开的凭据管道，绝不从环境变量、命令行、数据库或日志读取或保存供应商密钥。启动和恢复脚本必须从不含 `.env` 的独立工作树运行。

发送进程受 macOS 沙箱限制，只能连接本机专用 PostgreSQL 和拥有临时认证令牌的本机代理。代理是独立代码，仅接受 `CONNECT api.deepseek.com:443`，拒绝其他目标，且在建立外部连接前把一次性尝试标记同步到私有目录。它只转发 TLS 字节，不接收明文密钥或证据；客户端仍校验 `api.deepseek.com` 的 TLS 证书。这个代理是应用级固定目的约束，不是内核级外部 IP 防火墙，也不能证明生产网络隔离。

系统 DNS 可能返回 198.18.0.0/15 虚拟映射地址，因此该范围作为唯一明确例外与公网单播一同接受；RFC1918、环回、链路本地、组播以及混入任何不允许地址的结果均拒绝。接受虚拟映射不改变 TLS 主机名与证书链校验，也不允许配置其他域名或端口。

该工具先完成既有审批、资料授权、预览、原请求、租约、用量预留及一次性许可校验。原许可引用和保守的发送尝试标记均在发起连接前持久保存。即使发生超时、进程中断或数据库故障，也不自动再发。完整首答在加密暂存落盘后才入库并结算；重启 PostgreSQL 后仅执行原记录恢复两次，以核对不会重复记账，不调用发送接口。

真实用户界面、生产持久卷、操作系统重启及商业可用性均未验证；供应商失败或回答不符合合同不能当成业务建议成功。供应商不返回使用量时保守保留预留，不能显示为实际使用量。临时目录与密钥隔离只适用于本机合成试验；超过容量、磁盘失败与完整标记前崩溃仍需人工核查。

一次本机假服务完整链已验证：合成审批和资料、策略、预览、启动与用量预留后，经固定域名本地 TLS 代理收到模拟 HTTP 429；首答以失败状态保存，3 个模拟 token 入账。专用 PostgreSQL 进程重启后，重复两次仅恢复和核对，记录仍为一次调用且没有再次发送。运行时使用初版代理；本机假服务采用注入连接器，不调用后续虚拟 DNS 解析修改。六项代理、TLS、DNS 和沙箱端口隔离快测另已通过。上述结果不代表真实 DeepSeek 成功。

一次真实 DeepSeek 合成调用已完成：HTTP 200，但该次新申请的输出上限是 512，模型返回 `length` 而未完整满足结果结构。原答加密保存，供应商报告输入 6793、输出 512、合计 7305 token；数据库重启后重复恢复没有重复发送或计量。该次业务结果为失败，原申请及账本保持不变。

后续合成测试将创建全新工作区，在发布模型之前配置单次最大输出 8192，再对独立新申请设置相同输出容量；不修改或重发前一次请求。8192 是平台现有业务分析合同的单次输出上限，不是模型调用次数或金额限制。根据 [DeepSeek 模型文档](https://api-docs.deepseek.com/quick_start/pricing/)，`deepseek-v4-pro` 的供应商输出上限高于此值；这不保证任何一次结果必然完整，仍须保存并验证原响应。
