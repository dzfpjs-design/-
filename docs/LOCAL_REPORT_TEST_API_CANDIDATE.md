# 本机报告配置测试服务：受控启动候选

本工具仅负责启动和停止一个本机 API，不迁移数据库、不启动工作区处理器，也不处理报告或调用云模型。它不是升级授权、数据库备份或正式环境验收。

发布根目录需同时包含 `src/`、`static/setup/`、`model-packs/` 和 `runtime-packs/`。代码与静态目录必须是只读普通文件及只读目录；如需 `.runtime`，它只能是指向显式指定的既有运行时目录的链接，启动器不会遍历或复制该目录。启动前和导入 API 前分别核验工件摘要。运行期间仍应禁止更改发布工件。

启动时使用原有私有启动配置；监督进程只在原配置调用 Uvicorn 时替换代码和静态路径。原配置的数据库、`.env`、模型运行时、私有存储及其他选项保持原意；原配置文件需归当前用户所有且禁止其他用户读写，并以调用方提供的摘要锁定。启动器还会拒绝含额外进程创建或其他未知导入的启动脚本。

`serve` 先绑定指定的本机端口，端口占用时不会停止或覆盖任何已有服务。进程以前台方式运行，需要由操作者或进程管理器维持；`status` 和 `stop` 使用私有目录中的认证 Unix 控制通道，`stop` 只请求该服务优雅退出，不向记录的 PID 发送信号。应在 `serve` 进程确实退出、端口释放后，才使用旧启动方式回滚。

启动服务时应将标准输出和标准错误重定向到权限为 `0600` 的私有日志；被启动的应用自身仍可能输出错误信息，不能假设日志已脱敏或公开日志。启动器不运行或检查工作区处理器，正式切换前仍需单独确认处理器处于预期状态。

若进程异常终止并留下运行标记，状态为未知；本工具不会自动移除标记、重用状态或停止任何其他进程。先核对服务与端口，再由授权运维人员处理。原启动器、PID 文件和工作区数据均不由本工具修改。完整部署前必须另行完成数据库及私有文件备份、恢复演练、目标版本兼容和用户流程验收。

本地生命周期测试使用临时目录、假应用与本机端口；它不能证明 8766、真实账号或业务数据已验证。
