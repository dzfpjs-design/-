# 合成 DeepSeek 实际调用预检候选

此候选只保存不含原文和密钥的测试元数据，并验证本地一次性申请和模拟网络规则；它没有发起真实请求、读密钥或数据库的代码，也不授权派发。现有合成检查点的来源仍由既有离线生成与恢复护栏验证；调用者提供的哈希本身不能证明资料是合成的。模型名和模型哈希在预检记录中固定，真正调用前还必须与审批前已发布的模型、资料授权、原意图及专用 PostgreSQL 记录逐项核对。该记录不是用量账本，也不能替代数据库唯一约束。

一次性标记使用私有目录、独占创建和文件/目录同步；同一申请再次领取会拒绝。已领取但未能证明实际发送的状态按未知处理，不允许重发。必须保留原 intent、permit、数据库账本和加密首答，并在进程重启后用原记录做不发网络请求的恢复；当前仅有隔离实验实现，未接入正式操作界面或自动恢复。系统临时目录和同账号密钥不构成生产持久卷或机密隔离。

当前 macOS `sandbox-exec` 的 network 规则不能指定外部 IP 字面量；本候选仅能生成完全禁止外网、允许指定本机测试端口的模拟规则，live 出口配置会直接拒绝。`verify_dns_answers` 仅比较调用者提供的测试答案，不发起 DNS 查询，也不证明 TLS、网络规则或任何真实来源。

已有大疆隔离实验的 Linux guard 使用独立命名空间和 iptables-nft 默认拒绝，曾在专用 Ubuntu 虚拟机的合成跨子网场景验证单个目标 IPv4 和 TCP 端口。但目前 Docker Desktop daemon 不可用，既有生产检查要求原生 Linux 和可验证的本地 daemon；该 guard 未验证真实外网、DeepSeek、真实 DNS 或账本协同，也仅支持单目的地。不可在 macOS 上绕过这些检查。未来须在专用 Linux 测试环境验证目标 IP 与端口、固定主机名 TLS、DNS、防 IPv6 和代理旁路、独立 PostgreSQL 的安全连通方式、非目标连接拒绝、daemon/guard 异常、首答持久化与撤权竞争，再审查接入方案。

模型账号可用性、真实 DeepSeek 返回质量和费用、端到端业务价值、持久卷和密钥管理均未验证；不得把本预检或本地假服务测试称为实际调用成功。
