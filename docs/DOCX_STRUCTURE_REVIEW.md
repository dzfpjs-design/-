# Word 结构核对

配置中心资料处理进度提供按需的“核对 Word 目录与文本框”。该能力读取当前工作区已保存的原 DOCX，先检查存储身份和文件摘要，再返回有边界的只读结构检查。接口响应禁止缓存，不会写入配置、修改原件或替换历史正文块。

结构检查统计目录、文本框、兼容分支、修订、表格和图形等风险，并可列出顶层目录与文本框候选。兼容分支只选择一个可识别分支；不能确定时保留缺口提示。候选采用独立的主体序号和 XML 路径，**不是页码，也不是已确认的原文或业务事实**。目录只能作为导航；图片、修订、脚注及其他未覆盖内容仍须与原件核对。不可识别或超过资源限制的文件会明确失败，不返回截断结果冒充完整结果。

该功能不改变既有原生解析和块编号，不把候选直接送入业务事实、自动确认或执行。用户仍需利用本地副本、逐页识别及审核流程核对资料；检查到结构风险不能说明文档已完整解析。历史资料可按需检查，无须重跑解析或覆盖已有人工成果。

逐页识别界面还可以按需对照同一 PDF 副本冻结的可提取文字和该页原始 OCR 结果。该对照只忽略空白，不忽略数字、符号、标点或单位；两者可能一起出错或因阅读顺序不同而有差异，因此“未见差异”不代表文字正确，也不会保存修改或确认页面。文本不可用或超出单页上限时明确显示原因。请求校验当前工作区、原件、识别代次、页和原始版本，并使用私有不缓存响应；每次请求会重新核验来源，不适合并发批量读取所有页面。

访问权限沿用既有 OCR 读取语义：后续请求重新检查账号与工作区；已经通过认证并取得只读快照的在途请求，不保证在权限撤销提交后立即中断。这一限制适用于该对照，不能宣传为严格即时撤权。

已用合成文档验证兼容分支、嵌套文本框、错误 ZIP 和 XML、资源限制及旧块不变；API 检查工作区隔离、原件完整性和只读；组件覆盖加载、失败重试、分页、权限变化与迟到响应。本轮还对当前测试工作区中的实际 DOCX 通过正常 API 检查了目录和文本框候选。用户浏览器的登录态全流程、整份报告的人工核对及业务语义正确性仍需另行验证。
