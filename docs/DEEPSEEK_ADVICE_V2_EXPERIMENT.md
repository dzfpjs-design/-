# DeepSeek 业务建议 v2 实验分支

本分支仅保存开发中的隔离实验，不得部署、合并或在真实工作区启用。主线提供已验证的普通调用改造；本分支不能视为业务建议端到端完成。

阻碍包括：v1 正式接口与 v2 记录共存可能使历史查询失败；资料处理依赖有效用户会话，尚无跨角色、可撤销的后台授权；政策自然过期后缺少取消与恢复；文件与数据库事务不原子，仍需解决孤儿清理及文件路径安全。测试数据库标记仅用于减少误操作，不是生产安全边界。共享库存会被现有目标计数读取路径使用，不能把整个改动称为不影响正式代码。

在独立 PostgreSQL 和合成来源上，针对计划写入、同号重放、资料处理、隔离时间篡改、回滚及部分正式目标计数路径运行了定向测试。成熟目标的完整 v2 链、浏览器、真实工作区及真实云调用未通过验证；中断的测试不计为通过。

到期取消候选只在专用隔离测试库执行：原准备操作未开始且其原政策真实到期时追加取消回执，保留原 Plan/Job 与原请求编号；不同正文不复用回执，无隐式授权或模型调用。此状态仍不是生产取消流程：正式路由、全部旧写入口、跨版本新建、离线数据岗位授权、资料/审批并发、文件清理和实际成熟目标均未完成；旧 API/worker 混版仍不安全。测试使用构造的合成历史事实，不代表真实任务或真实时间演练。

当前集成分支的 Start 实验曾在独立 PostgreSQL 重现目标检查后、事务提交前自然过期，以及证据云授权在检查后被另一事务撤回而 Start 仍可提交；候选修复已通过隔离测试，并在合成成熟目标/审批链验证至租约环节。发送 Job 尚处于隔离停放状态，正式发送未接入；禁止将此分支部署或合入主线。必须证明提交时新鲜度、原审批/证据撤权及锁顺序，再继续发送链。索引保护会串行化 audit_events 上相关处理并与维护冲突，来源集合文件处理和离线岗位委托尚未统一，文件孤儿清理及旧版写入兼容未完成。集成时恢复测试只用于专属合成数据库，不能用于真实工作区。

## 最近的验证边界

- 在专用 PostgreSQL 和合成资料上，两级审批、目标发布、资料授权、预览、同号回放、Start 和领取租约曾完整通过；这条链耗时约 575 秒，未调用云服务。另一次扩展到云账本的测试耗时约 701 秒，在意图记录和网络发送之前失败：新预留被旧容量库存视为未知记录。修复后，在相同隔离条件下重跑完整成熟合成链约 871 秒，测试服务接收一次本机请求，原首答入账且原请求不能重复发送；无真实 DeepSeek 或用户资料。该长测使用原本机发送器，不代表新版暂存候选已完成成熟链验证。隔离账本不可作为真实账本记录。
- 单独的本机 HTTP 测试覆盖一次性发送、超时、响应压缩、撤权竞争和进程中断；这些测试使用替身，不等于真实审批链、DeepSeek 或生产环境验证。响应原文保全与原日账本结算仍须和真实成熟链一起复核。
- 索引与锁保护仍会使不同工作区相互等待或返回冲突，资料重读期间持锁的耗时不适合直接投入使用。不得仅凭测试服务一次请求成功就开放正式 worker。
- 目前没有验证真实工作区的数据库迁移、完整备份恢复、认证页面和后台进程，也没有升级 8766。旧任务状态不明时不得自动重发或由新 worker 领取。
- 离线资料岗位授权候选已在合成的两级审批资料上验证登录授权、退出、独立进程整理、重新登录查看及进程退出后的离线状态；准备入口仍为测试适配器，接口和 worker 默认关闭并限制专用测试库，来源写入方锁序尚未完整验证。
- 首答暂存候选能在完整加密暂存后恢复入库，但完成标记前崩溃或磁盘故障仍可能丢失首答；尚无操作员恢复入口和生产密钥、容量管理。供应商超时配置也需要真实模型时延证据。旧版记录在新版预留或发送意图存在时的正式查询和同号回放仍会被拒绝。这些问题均阻止正式部署。

性能优化的待验证方向：在私有区域先生成有界的不可变资料快照，再以短事务锁定并重新核验来源版本、资料摘要、审批、岗位、撤权和有效期后提交元数据。不得直接移除索引保护锁或跳过最终授权校验。需要先解决共享文件其他写入者、孤儿文件及崩溃恢复，并通过不同工作区慢读和并发撤权、修改、过期、回滚测试。上述方案尚未实现，不代表锁争用已经解决。

DeepSeek 不限额候选不再用其他工作流的 Goal 调用和步骤预算拦截业务建议，仍执行原目标与版本库存验证、原申请单次派发和用量记录；其他供应商及旧工作流的额度规则不变。在专用 PostgreSQL 上完成的成熟合成链使用计数替身模拟其他工具预算已耗尽，经过一次本机模拟调用和结算；该验证不等同于真实云或正式接口。另一个未解决的长期限制是任务历史库存的单次扫描上限：大量历史记录仍可能使后续操作待核，不能将此候选称为无限次使用。

资料 intent 登记候选已把全局索引门禁推迟到来源读取完成后、检查原登记和写入之前。专用 PostgreSQL 测试中，人工阻塞登记时的来源读取，另一工作区仍能取得门禁；若另一事务继续持有门禁，原登记会在写入前拒绝。补充的真实合成审批资料与文件测试证明该登记完成后仍可使用相同原申请处理和回放；仅使用本地数据、云调用为零。政策在慢读时自然过期也会拒绝登记。这个调整只改善登记阶段；后续文件保存和资料回执阶段仍会在全局门禁内读取文件，完整业务链性能、生产多工作区吞吐与真实用户流程均未验证。
