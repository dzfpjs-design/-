# 业务建议首答暂存实验（不可生产发布）

此候选默认关闭，只有专属一次性 PostgreSQL 测试库能通过既有护栏；没有正式路由或自动重发。测试根目录必须是系统临时目录下以 `advice-v2-response-spool-` 开头的当前账号私有目录。不得指向报告目录；本模块不读取报告。配置 `v2_response_spool_enabled`、`v2_response_spool_root` 和既有派发开关仅用于隔离验收。正式发布仍须实现持久密钥管理、可用性、容量、受控清理、权限隔离、运维与迁移。

处理流程：签发一次性 intent 和 permit；验证原身份链，将收到的 HTTP 原始字节流以 AES-GCM 写入私有文件并逐块同步，消息头先做白名单过滤；只有响应流正常 EOF 后才同步写认证完成标记。数据库在下一事务验证原链并保存原字节，之后独立结算原日账本。已完成文件保留，`recover` 可重启后重新验真、幂等保存和结算；它不发送网络请求。断线、文件写失败、容量不足、超时、进程在完成标记前崩溃均为状态未知，不产生重发许可。保存已完成标记前的崩溃窗口仍可能丢失付费首答，不能声称零丢失。完成标记同步失败时尽力移除标记；如果磁盘故障或崩溃使移除也失败，无法仅凭该文件判断其曾经同步成功，必须人工处置，不能视为已发送或未发送的证明。

本地 key 和目录为 0600/0700，检查所有者、链接数、禁止符号链接，完成标记经 MAC 验证且内容经 GCM 验证；同一操作系统账号及持 key 者不在抵抗篡改边界。单文件上限 16 MiB、最多 4 个槽位；没有自动回收或不完整记录删除。即使已经入库和结算，也先保留文件；测试人员仅在完成验收并确认数据库持久、结算之后，销毁整个专属临时环境。没有任何生产清理策略，满额阻塞是明确可用性缺口。

连接、读和总超时默认分别 10 秒、120 秒和 600 秒，且受配置上下限约束；async 总时限覆盖网络流，但同步磁盘 fsync 若阻塞不能保证硬实时上限。合法 permit 提交后不可撤回；撤权先提交则签发失败，permit 先提交后可能已发送。发送过程中无数据库长事务，但原始来源、permit 的全表锁以及慢文件核查仍是吞吐和维护阻碍，不得静默作为生产实现。此实验并未测试真实 DeepSeek、真实报告或实际产品业务价值。
