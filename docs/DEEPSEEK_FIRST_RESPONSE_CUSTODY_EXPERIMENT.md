# 原始首答本地保全实验

本分支仅适用于专用隔离 PostgreSQL，不含网络发送、正式接口或后台 worker。持久 intent 表示发送结果未知，不能证明请求已发送、未发送，也不授权重发。

实验在一次事务中保存 BYTEA 原文、SHA-256 与独立 Audit 回执；唯一约束和表锁约束合作的测试写者。同原文和回执可重放，不同原文、残缺或不一致拒绝；无已保存首答时明确返回未知且不授权重发。写入调用方必须在丢弃内存原文前提交；进程在收到回答与提交之间崩溃仍存在丢失窗口，不能因此推断未发送。

固定历史验证器按数据库原件校验工作区、实际测试版预留 claim、Start、租约、预览、intent 和 CloudCall 的绑定、唯一性、原始哈希及签发时序；恢复不依赖当前会话、角色或租约仍有效。提供给回应的模型名称取自冻结预览，发送者必须保证实际 HTTP 回执来自该调用。此验证遵循既有应用和协作写者的权限边界，不保证抵御能够同时伪造所有数据库记录的管理员；不等同于实际外发授权。

隔离数据库联测调用了实际测试版预留、intent、原文保全、解析与用量结算逻辑，验证重连恢复、撤权与租约过期后的保全及异常拒绝；其目标、资料和审批使用合成测试替身，原文也为本地生成，未发生云端发送。尚未连接真实成熟审批、正式 API、真实模型响应、生产工作进程或生产存储恢复，不能视作产品功能完成。

原始 HTTP body 保持原字节。回执只接受固定字段和受限的 content-type、content-encoding、x-request-id，禁止 Set-Cookie、Authorization 等其他头和任意扩展字段进入 Audit；压缩 body 使用受限解码。早期不符合白名单的历史回执读取时拒绝，不会自动删除、重写或声称已完成迁移；此前若存在真实敏感记录，需要单独、安全的处理方案。
