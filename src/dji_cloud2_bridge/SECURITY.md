# Cloud API 2 连接安全边界

当前代码只开放配置保存、核对和撤销；真实 SDK 运行入口硬性关闭。Java 桥和隔离替身测试不构成大疆底座或模拟器联调结果。

## 阻塞原因

已在网络隔离的测试容器、临时测试 CA 和虚构凭据下复现：所检查的 DJI FlightHub SDK 3.3.7 对带自定义鉴权头的 HTTPS 请求跟随重定向时，会将该鉴权头发送至重定向目标。只限制初始 IP 与端口、验证 TLS 证书或去除代理环境变量不足以解决这一问题。有关源码参见[大疆固定版本的 HTTP 请求实现](https://github.com/dji-sdk/Cloud-API-2/blob/fd679f89301295e3c2085a90dac1d5750cfa563d/sdk/deps/base/common/http_client/http_request_sync.cc)。

另在大疆公开源码中发现消息连接可能将编码后的鉴权信息写入日志；实际启用前必须验证原生和 Java 日志均不泄露。不得将编码视为加密。

独立实验还针对公开源码 3.4.0 构建了临时修改版：禁止 HTTP 重定向后，302 仍触发跨端口 WebSocket 请求，目标请求的 `Sec-WebSocket-Protocol` 包含可逆编码的合成鉴权值。实验版没有纳入项目或启用；仅修改 HTTP 重定向无法消除消息通道的风险。

随后对 SDK 和其使用的 libwebsockets 同时制作了[研究用补丁与可执行合成回归](experiments/README.md)。干净构建后的实验版通过五类 3xx、四类重定向目标的正反对照及一次正常 HTTP/WSS 路径的默认和 DEBUG 日志检查；未验证完整 SDK 日志和所有网络路径。源码补丁不是经过大疆认证的发布包，不包含官方二进制，也不能单独证明生产安全。

## 已验证与未验证

工作区隔离、凭据加密、授权范围、原操作的幂等核对、撤权栅栏与替身进程断线重启可通过项目测试执行。官方 SDK 的 Java 桥已针对 3.3.7 二进制编译，未与官方底座联调。SDK 的初始化回执不代表连接成功；设备列表查询成功也不证明消息通道连接成功。

隔离研究中，在 Docker Desktop 的独立网络命名空间设置默认拒绝出站、仅开放一个测试 IPv4 和 TCP 端口后，官方 SDK 不能将请求重定向至另一个测试 IP 或端口；非 root、无 Linux capabilities 的 SDK 容器不能更改规则。DNS、代理和 IPv6 旁路尝试被阻断。研发模块随后增加专建内部网络、两阶段检查、守护租约和停止回执；当前 macOS 环境无法证明 Docker daemon 的宿主命名空间，因此新版模块在启动前失败关闭。早期链路测试不能当成新版通过证明。内部测试网络不能直接访问外部局域网，正式出口控制尚未完成。IP 和端口过滤也不能识别同地址虚拟主机，必须结合应用层防护。

随后在独立 Ubuntu 24.04 ARM64 虚拟机和直接监听 Unix socket 的 dockerd 中，使用独立 PostgreSQL、修复版 JNI、临时 CA 和合成服务执行了[联合测试](../../tests/dji_cloud2_e2e/README.md)：覆盖查询、跨地址出口限制、授权变更和撤权竞争、guard/主管异常退出及持久记录。测试专网只能连接容器内的测试服务；默认 systemd socket activation、实际 LAN、大疆底座和官方模拟器均未验证。主管异常退出后即使测试进程清除了有标签的资源，由于没有可靠的原始断网回执，台账仍保留 `cleanup_unverified` 并阻止自动重启。Docker 创建结果未知且稍后完成的情况目前仅以数据库测试模拟，尚未用真实延迟的 daemon 完整复现。

撤权测试中，切断出口后已缓冲的数据仍可能被读取；必须先关闭网络出口，再终止进程并在数据库侧拒绝迟到结果。不得承诺撤回已经发送或缓冲的数据。

## 启用前必须完成

1. 在受支持的 Linux 运行环境中实现并验证逐连接的默认拒绝出口、严格限定地址和端口；验证容器没有网络管理权限、Docker socket 或不必要的宿主资源。
2. 验证应用层重定向处理及各种 HTTP 状态不会泄露凭据或误报查询成功，并检查 HTTP、WebSocket 和原生组件的日志。
3. 验证防火墙初始化无放行空窗、已有连接撤权、父进程与容器异常退出、守护器或 Docker 重启、孤儿清理及数据库故障后的恢复。
4. 核对 SDK 版本、供应链及闭源和第三方依赖许可；在正式底座和官方模拟器上验证工作区隔离、HTTP 与消息通道鉴权和断线恢复。

在上述验证完成并经安全评估前，不得修改 `dji_cloud2_runtime._command()` 的硬性禁用状态。

## 授权代次迁移与恢复

Cloud API 2 新授权绑定数据库内用户及成员的身份和权限代次。权限变更后恢复原角色，不会让旧授权自动复活；旧记录缺少代次时需由管理员撤销并重新新增。迁移仅添加 Cloud API 2 专用列和触发器，不改变其他网关的授权判断。

迁移应先停止相关写入并制作可恢复备份，再由具有 DDL 权限的维护账号在确认目标数据库后执行 `generic_agents.dji_cloud2_auth_epoch.migrate(engine())`；迁移需要短暂独占身份表，数据量大时需安排维护窗口。触发器或版本标记异常不会自动修复，Cloud API 2 会失败关闭。运行账号不应能禁用或替换触发器。

恢复旧数据库快照可能同时回滚用户权限、代次和授权记录；恢复流程必须使所有 Cloud API 2 授权失效，或使用独立且不会随数据库回滚的恢复代次。旧版 worker 不知道代次机制，因此升级应停止旧版；如需回滚，应先保持真实连接硬禁并隔离旧运行器。
