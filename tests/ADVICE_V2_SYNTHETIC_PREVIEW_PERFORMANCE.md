# V2 建议预览：隔离合成数据性能剖析

本记录对应原始测试提交 `640803b`、PostgreSQL 17、真实审批流程生成的合成成熟目标。测试在专属临时数据库及文件目录中运行，云凭据为空，系统网络隔离仅允许连接测试数据库。未使用正式数据库、真实报告或模型调用。结果不是 8766 或生产环境的性能指标。

## 单次采样基线

采样版完整测试 256.64 秒，包括准备资料、生成预览及关闭连接后同号重放，不能将其全部视为一次预览的耗时。

| 阶段 | 耗时（秒） | SELECT 次数 |
| --- | ---: | ---: |
| 政策授权 | 13.78 | 2,249 |
| 创建资料准备任务 | 52.86 | 8,821 |
| 文件登记 | 0.69 | 125 |
| 资料处理 | 53.41 | 9,052 |
| 框架构建与资料授权 | 57.15 | 10,447 |
| 首次预览 | 64.27 | 11,526 |
| 同号重放 | 11.58 | 1,978 |

全程共有 44,519 次 SELECT，驱动层 execute 累计约 19.41 秒。该统计不含完整 ORM 结果构造和所有 Python 处理，不是数据库服务端 CPU 时间。50 毫秒调用栈采样显示：成熟目标与评价记录的逐层校验、存储载荷解码、JSON 序列化/摘要及 ORM 查询反复出现在调用路径中。采样和阶段计时会引入测量开销，单次运行不提供置信区间。

## 试验和边界

曾仅在隔离分支删除一次紧邻且由下一次解析再次执行的字符串检查。原有解码等价、非法输入、数据库并发和预览测试通过；同一合成流程重测 257.21 秒，首次预览 65.20 秒、重放 12.02 秒，未观察到性能改善。该通用解码改动已撤销，没有接入或建议合并。

附加试验中的角色变更、另一事务撤权测试通过；新增字符串调用次数的断言失败，因为测试漏算了 projection 对同一字符串的检查，不属于通过证据。先前探索的 ContextVar 解码缓存无法证明跨 Session 隔离，也已撤销。现有业务对来源、身份、期限、摘要和提交前状态的检查均未删除。

目标/资料校验和查询在单次任务中多次重复，是下一步分析重点。不得仅依据相同记录 ID 或相同事务就跳过复核；READ COMMITTED 下并发写入、撤权、事务及 savepoint 边界都需要单独证明。潜在优化需在完整用户工作流、并发撤权和生产式数据规模上验证。

## 再现方式与限制

`tests/advice_preview_profile_plugin.py` 是可选的只读采样插件，仅记录阶段、SQL 首词类别与函数名，不记录 SQL 参数、文档、账号或模型密钥。50 毫秒采样跨线程聚合，不能解释为精确函数 CPU 时间。此插件是用于复现采样方法的整理版本；原始数据由同等逻辑的临时插件生成，未对整理版本重跑完整流程。

仅在满足以下全部条件时运行：新建并独占临时 PostgreSQL 集群，使用专用无密码测试用户与空测试库；提供 `GA_TEST_DATABASE_URL`、`GA_TEST_PG_DATA_DIR`、`GA_TEST_PG_SYSTEM_IDENTIFIER`；使用私有合成检查点 `GA_SYNTHETIC_FRESH_CHECKPOINT`；清空所有云凭据和云服务允许列表；操作系统网络沙箱只允许该 PostgreSQL 端口。检查点必须是 `tests/synthetic_advice_fresh_checkpoint_restore.py` 接受的合成数据，禁止使用真实资料。设置 `GA_SYNTHETIC_PROFILE_OUTPUT` 为系统临时目录中尚不存在、以 `ga-synthetic-advice-profile-` 开头的绝对文件路径，插件以 0600 排他创建报告。

满足隔离前提后，可在该代码快照运行：

```sh
pytest -q -s -p tests.advice_preview_profile_plugin tests/test_advice_v2_real_fresh_preview_candidate_pg.py
```

本记录保留实验数据，不代表任何真实用户业务流程、上线准备、权限或业务价值验收已完成。

## 批量读取负例（独立 PostgreSQL 17）

热路径 `_acks` 中，source 和 extractor 的 Capability 原来分别执行 `populate_existing` 读取。在 READ COMMITTED 下，两次读取有各自的语句快照；第二次读取还能刷新同 ID 的 ORM 对象。`tests/test_goal_ack_batch_read_safety_pg.py` 仅把一次 `IN` 查询作为测试对照，不改业务实现。

无并发时，对照查询可将该单个读取对从两条 SELECT 降为一条，并得到同样的值；但当 extractor 在两次原始查询之间被另一事务更新时，原实现读到更新后的摘要并拒绝旧 pin，一次性预取可能继续拿到旧值。测试分别覆盖两个不同 ID 和相同 ID 的 ORM 别名；另一事务撤销角色后也确认重新认证会失败。测试全部通过，证实简单批量化会改变安全结论，故未接入。该对照仅量化单个读取对的语句数量，不能推算整个预览的性能收益。

在已经持有全部相关行锁的特定调用路径中，批量读取或有可能可行；目前尚未证明热路径普遍持有这些锁、所有写者遵守相同锁协议或锁序安全。因此保留现有读取，不通过缓存、跳过完整 payload 或提前预取绕过这一问题。
