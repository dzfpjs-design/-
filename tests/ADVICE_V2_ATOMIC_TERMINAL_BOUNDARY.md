# 业务建议原子终态实验边界

本实验仅可在身份校验的专用 PostgreSQL 中建立独立测试表；没有路由、worker 或生产迁移。它在同一数据库事务中，对已完整保全的首答核验来源链、按已证明的供应商用量结算、写入关联终态及前后日账数据。重入只校验原回执，不重新发送或重复计量。提交前重新校验记录与日账，事务回滚不会留下终态。

没有可信供应商用量、无首答或链条不完整时保留原预留待核。旧调用若已结算但没有同事务终态，不能事后凭现有日汇总补造证明。失败响应即使有用量也仅标记失败，不表示产生业务建议。

默认关闭且限定专用 PG 的库存分支可识别原子终态；显式测试开关启用时，既有隔离结算器写入该终态。合成 Goal/资料替身测试已走完两个不同申请及两次本机假服务结算。它不改变旧 Plan/Job 状态，也不自动授予发云或重发权限；未知结果仍阻断。记录及约束依赖测试库可信写入方，历史摘要不提供对任意恶意数据库写入方的独立认证。需要生产级唯一约束、受限写入、可信逐笔账和迁移策略，并覆盖旧写方/崩溃/并发/自然日切、完整审批资料及真实界面后，才可考虑接入。

现有跨版本库存 `_rows` 有 1000 条硬上限，并在事务内反复读取历史文件与全局账本；每个申请可能产生多个记录，长期使用会被上限阻断。两次模拟通过不证明不限次数。须设计一致快照下的键集分页、数据库侧反向孤儿核验与可控内存使用，同时识别不遵守任务锁的旧写方；未完成前不能声称真正不限额。

实现复用测试库全表门禁保护库存与终态写入；它可能影响其他工作区吞吐，尚未验证所有写方锁序，也不能作为生产锁方案。进程重建测试仅覆盖数据库连接重新建立，不代表 PostgreSQL 进程或操作系统重启恢复。

另有独立终态分页扫描实验：专用 PG 中以稳定 Plan ID 键集按最多 128 条逐页读取，逐条核验并在数据库侧检查无法关联的终态审计；扫描自身不授权新请求，也不检查所有非终态记录。测试使用 READ COMMITTED：身份检查后先取得相关表的共享门禁，再读任务和分页数据，避免在门禁前建立过期快照；不能把此前已建立的 REPEATABLE READ 快照当作锁后最新状态。为拒绝不合作旧写者，实验在扫描期间持有全局表锁，而且每条核验会重新核对当日日账，时间和并发成本未解决，绝不用于生产。1001 条分页测试只合成元数据并替换逐条终态校验，不能代表 1001 次真实业务调用；另有显式 xfail 验收测试记录现有实际库存的 1000 上限仍未修复。

与恢复和旧版历史实验同时启用时，服务端先完整核验终态再从活动预留集合中排除；已恢复的终态结算仍在同一事务执行用户授权回调及提交前会话时效检查。目标预算的只读快照在无终态时沿用原显示；有终态时当前明确返回待核，真正的无锁只读终态核验尚未完成。上述均为专用 PG 的隔离测试，不是正式部署入口。
