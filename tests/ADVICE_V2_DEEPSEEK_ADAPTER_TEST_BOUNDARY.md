# V2 DeepSeek 派发和结算候选边界

此分支是隔离验证候选，不安装产品路由或常驻 worker；`GA_V2_DEEPSEEK_DISPATCH_ENABLED` 默认关闭。即使设置开启，现有 permit、账本、原始首答表仍强制专属临时 PostgreSQL 数据库身份，不能用于 8766 或正式数据库。没有向真实 DeepSeek 发请求，没有使用真实模型密钥、用户工作区或可研报告。

候选的正式地址路径复用云网关 `_resolve_cloud_access`：检查服务端 provider allowlist、固定 DeepSeek HTTPS 地址、`DEEPSEEK_API_KEY` 引用和同一凭据解析规则。HTTP 禁止代理环境和重定向。该路径仍依赖测试专用预留、intent、短期一次性 permit 和首答原件表；不存在接入正式服务的能力，也没有为通过测试而跳过原账本或发送前验证。

`execute_synthetic_test_only` 使用同一发送、首答保全和结算逻辑，但只连接独占测试环境下 127.0.0.1 的合成 HTTP 服务，绝不读取供应商密钥。实际正式地址路径仅用 HTTPX 进程内 MockTransport 验证固定地址和合成密钥，未发生 DNS 或真实网络连接。合成业务来源和 Goal 使用测试替身；这不证明真实 DeepSeek、真实来源质量或真实用户流程。

HTTP 首答完整原始 body 在独立事务先保存，随后另一个独立事务从原件解析、核验供应商 usage，并结算原 CloudCall 的 day 日账。没有可信 usage 时按预留量保守记账，不伪造零；非 200 或无效内容仍保留原件并按已知事实结算。服务重启后可从已保存的首答恢复结算，不再次 POST。用户读取另行验证真实当前会话；返回的结构化模型答复明确 `business_result_verified=false`，不冒充已核验业务建议或审批结果。

合成测试覆盖成功、断连、非 200、gzip wire bytes、敏感 Set-Cookie 过滤、大小与慢流限制、首答提交后子进程真实退出及不重发恢复、permit 后凭据轮换与停用、HTTP 期间数据库锁可取得并提交撤销。usage=3/2/5 的测试验证结算原 CloudCall.day 和幂等；此 usage 来自合成服务。实际响应超限/超时或首答提交失败时只保留 unknown 和禁止重发，不能称其原答已保存。

## 正式部署阻碍

- 真实 DeepSeek 连接、凭据、供应商 usage、费用与延迟均未验证；本次明确没有真实调用。
- V2 核心原件、一次性 permit、账本唯一约束和首答表均为测试专用，不具备正式数据库迁移、完整故障恢复或旧/外部写者隔离证明。
- permit 提交前已完成撤权则拒绝；permit 先提交后本次发送可能继续，相关人工确认、撤权 UI 和可理解的回执未实现。
- 预留与 permit 在来源复核及证据文件读取期间仍持测试表锁；影响其他工作区吞吐，不能直接上线。短锁/唯一约束替代需证明并发、撤权、孤儿与 DDL 安全。
- 16 MiB 原始响应、1 MiB 解码响应及响应头白名单是候选限制；不可解析或超限不会自动重发。原始响应可能包含敏感数据，正式数据库权限、保留和清理方案尚未验收。
- 未实现业务语义引用核验、可审阅结果的持久化及产品界面；“模型运行”不等于业务价值或端到端交付。
