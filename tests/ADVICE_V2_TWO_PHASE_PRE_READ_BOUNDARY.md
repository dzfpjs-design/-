# 业务建议资料两阶段处理：实验边界与待办

此分支没有实现两阶段提交，也没有改动任何正式 API、worker、权限或写入路径。`test_advice_two_phase_source_pre_read_candidate_pg.py` 仅在专用 PostgreSQL 和真实审批结构生成的合成资料上，验证两个前提：不取得资料全局索引门禁的预读遭遇慢本地读取时，另一个工作区可以取得门禁；预读得到的字节不是授权，在此后岗位变更或原资料引用被篡改时，重新验证会拒绝。测试还检验回滚的资料修改不会当作提交，且没有云调用。它不证明预读可安全用于生产写入，也不证明本测试之外的并发或恢复安全。

## 当前不可直接上线的原因

- 现有 `require_committed` 持有审计表自冲突锁至事务结束；后续来源校验、内容保存和原件校验仍在该事务内。即使增加单独预读，不修改提交阶段也不会解决慢 IO 持锁。
- 当前资料文件是跨业务共享的内容寻址文件，旧写入方不遵守新锁协议。不能仅以路径、文件名、缓存对象或过去的摘要证明后续读取仍是同一内容，也不能在回滚后盲删潜在共享文件。
- 资料选择、审批、岗位、会话、政策有效期、证据授权、源文件和索引 DDL 都可能并发变化；把内容搬到锁外不能把旧结果当成当前授权。测试中的直接数据更改只用于证伪快照授权，并非真实业务撤权流程演练。
- 源文件、私有暂存与数据库不是同一事务。文件 fsync、落库、进程崩溃、目录篡改、替换及并发清理的恢复约束尚未实现，不能声明快照不可变或可恢复。

## 实现与验收顺序

1. 限专用测试库定义具有工作区、任务、来源版本、资料内容摘要与大小、创建状态的临时快照及权限隔离；针对每个真实来源写入方建立不可变文件协议和引用/回收规则。不要将测试数据库标记视作生产安全边界。
2. 在无全局审计门禁的阶段生成有界快照，安全打开文件并验证真实来源，写入私有位置并完成文件和目录持久化；失败时记录可诊断状态，不创建可使用的资料回执或调用许可。
3. 短事务内按统一锁序重新核验原身份和岗位、全部审批及撤权、会话及政策时钟、资料版本和摘要、目标、唯一性索引与文件引用；提交使用的字节须与验证的不可变快照是同一份。提交前重新检查时效，不能只依赖预读时间。
4. 完成记录和文件引用原子绑定，故障恢复必须能够区分未提交、已提交、未知状态；不能以未知状态推断未发送，也不能删除可能被其他记录共享的文件。
5. 在真实 PostgreSQL 上构造慢读下两个工作区、审批撤回/岗位撤权/资料改动、政策自然到期、会话退出、文件替换、事务与保存点回滚、进程强制退出、重启与旧写入方并发；逐项证明不会提交过期或撤销的内容、不会误删共享文件、不会重复发送，同时记录锁持有时长和成功吞吐。再针对真实界面、持久系统及生产式数据做验证。

当前测试不验证上述第 2–5 项，因此不能据此升级 8766 或宣称性能问题已修复。
